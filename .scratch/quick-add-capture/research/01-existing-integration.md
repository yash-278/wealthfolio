## Answer

Quick Add can reuse activity validation/storage, category rules/history, settings, provider configuration and token primitives. It still needs its own intake orchestration and durable capture lifecycle; the existing chat draft/commit pair is not a complete unattended ingestion API.

## Decision options for charting

- Reuse current PAT storage with a capture-specific permission and HTTP middleware adaptation, or use separate intake credentials. Neither is already implemented.
- Reuse core activity and classification logic through a combined write operation, or persist an explicit partial/retry state. Existing two-call composition cannot promise atomic success.
- Preserve source transaction references and request identity separately; use the current semantic fingerprint as one reconciliation signal, not proof that every similar alert is a duplicate.
- Use shared provider configuration with a feature-specific model override, or inherit the assistant's default; model changes should be an explicit feature contract.
